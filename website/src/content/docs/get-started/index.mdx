Start with the MCP client you already use. For a client and server on the same machine, local stdio is the smallest trust boundary and does not open a network listener. Docker Compose and Streamable HTTP remain available when you need a persistent service.

<span id="before-you-begin" class="legacy-anchor" aria-hidden="true"></span>

## Prerequisites

- A Trello account with an [API key and token](/trello-api-key/).
- Docker with Docker Compose, or Node.js 24.x with the repository's pinned pnpm version.
- An MCP client that supports Streamable HTTP or stdio.

<Aside type="caution" title="Treat the Trello token like a password">
  `TRELLO_TOKEN` can read and change resources visible to the member who authorized it. Keep both Trello credentials in a private client configuration, ignored `.env`, or deployment secret, and revoke the token at Trello if it leaks.
</Aside>

## Common path

<Steps>

1. **Choose the client.** Prefer its private user-level configuration or secret store.

2. **Choose the trust boundary.** Use stdio for a client-launched local process, the published Compose service for a persistent installation, or the local Compose build when you want to run checked-out source over HTTP.

3. **Set the Trello credentials.** [Create an API key and token](/trello-api-key/), then keep `TRELLO_API_KEY` and `TRELLO_TOKEN` in an ignored `.env`, client secret store, or deployment secret.

4. **Protect HTTP when required.** Keep Compose published to `127.0.0.1` for same-machine use. If you deliberately make it reachable from a network, add `MCP_AUTH_TOKEN`, HTTPS, and suitable network access controls.

5. **Verify discovery and one read.** Health endpoints are only process checks. Approve only the supplied `auth_whoami` call to verify the complete MCP and Trello path without changing a board.

</Steps>
