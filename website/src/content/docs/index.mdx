## Make your MCP client create a Trello card for you

This example creates one real card in an existing list in your connected Trello account. Your MCP client can discover the board and list IDs, so you only need to choose the destination and supply a card title.

```text title="Card creation example prompt"
Show me my Trello boards.
Ask me which board, list, and card title to use.
Show me the proposed card_create call and wait for my confirmation.
```

<Steps>
1. **Choose the destination.** The client calls `list_boards`, then passes the selected `boardId` to `board_lists`, so you can choose an existing list without finding IDs yourself. Both calls are read-only.

2. **Review the proposed call.** Confirm that the client proposes `card_create` with the intended `listId` and non-empty `name`. Those are the only required inputs. It is a write action that creates one persistent card.

3. **Create the card.** Approve the write. trello-mcp creates one persistent card in the chosen list and returns it to the client. The card appears in that list; if this was only a test, use `card_archive` instead of permanently deleting it.
</Steps>

## Choose how to run trello-mcp

Create a [Trello API key and token](/trello-api-key/), then choose the path that matches where the server should run. Both paths expose the same {TOOL_COUNT}-tool surface.

<Tabs syncKey="transport">
  <TabItem label="Docker / Streamable HTTP">
    Run trello-mcp continuously as a local container or service. Trello credentials stay with the server; clients connect to its `/mcp` URL.

    ```bash
    git clone https://github.com/enthouan/trello-mcp.git
    cd trello-mcp
    cp .env.example .env
    # Add TRELLO_API_KEY and TRELLO_TOKEN to the ignored .env file.
    docker compose up -d
    ```

    Point a local Streamable HTTP client to:

    ```text
    http://127.0.0.1:3000/mcp
    ```

    Keep the default loopback bind for local use. A remote deployment needs an intentionally reachable HTTPS endpoint and additional access controls.
  </TabItem>

  <TabItem label="Local stdio">
    Let an MCP client launch a built clone on the same machine. The client passes the Trello credentials to the child process.

    ```bash
    git clone https://github.com/enthouan/trello-mcp.git
    cd trello-mcp
    corepack enable
    corepack prepare pnpm@10.34.1 --activate
    corepack pnpm install --frozen-lockfile
    corepack pnpm build
    ```

    Configure the client to run:

    ```bash
    node /absolute/path/to/trello-mcp/dist/index.js
    ```

    Pass `TRANSPORT=stdio`, `TRELLO_API_KEY`, and `TRELLO_TOKEN` in the child-process environment. Use the client-specific examples below so secrets stay out of source control.
  </TabItem>
</Tabs>

Continue with the [complete setup guide](/get-started/) or review the [security model](/security/) before exposing an HTTP deployment.

Use natural-language requests in an MCP client to search, inspect, and maintain the Trello resources your configured token can access.
